# Measured results

`runs/run1` to `runs/run10` hold the output of `run-all-v2.sh`, one run per folder, 12 files each (Dart appears twice: `dart.json` runs it as it builds, `dart_aot.json` runs the precompiled program). Every run used all eight cores of one rented server, inside the image built from the `Dockerfile` in this repository. The `kotlin.json` files in `run1` to `run10` come from before the Kotlin timing fix in commit `6240b7f`, and `runs/kotlin_after_fix` holds ten runs after it.

`jmh-java.json` and `jmh-kotlin.json` are the JMH output for Java and Kotlin with default tiered compilation, and `jmh-java-tiered-off.json` and `jmh-kotlin-tiered-off.json` are the same runs with `-XX:-TieredCompilation`. The website uses the tiered-off pair, because it gives the smaller ratio (Java 5.4 against 7.9, Kotlin 7.0 against 8.6), and `benchmarkdotnet.txt` is the BenchmarkDotNet table for C#. `../harness/medians_v2.json` holds the numbers the website uses: medians of the ten runs for most languages, JMH with tiered compilation off for Java and Kotlin, and BenchmarkDotNet with tiered compilation off for C#.

`googlebenchmark-cpp.json`, `go-testing-bench.txt` and `mitata-typescript.json` are the checks for C++, Go and TypeScript, run by `harness/checks/run-checks.sh` over the same scenario code. The website uses these three instead of the hand-written loops, because each gives the smaller ratio (C++ 15.1 against 17.7, Go 15.4 against 23.2, TypeScript 4.4 against 5.8). Python, Ruby, PHP, Swift and Dart still come from the loops.
